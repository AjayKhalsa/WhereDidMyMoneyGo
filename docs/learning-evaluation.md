# Read-only learning evaluation

Run `node --experimental-transform-types --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --import ./tests/loader.mjs scripts/evaluate-learning.ts /private/path/input.json`. Add `--details` for private per-transaction results. Keep exports and detailed output outside Git. Input contains `transactions` in domain format and category metadata (`id`, `name`, `parentId`), without credentials or email bodies.

Export only manually reviewed/corrected expenses using the same evidence criteria as `learningData`, excluding Other, adjustments and machine enrichment. The evaluator holds out the latest transaction per normalized merchant only when at least three examples occurred on earlier dates. It rebuilds historical rules using earlier examples, then calls the existing Gmail categorizer. It excludes saved production rules because their training history could contain the holdout label. Same-day transactions cannot train each other. It never persists rules or changes ledger labels.

The inspected dataset contained 186 reviewed expenses and 126 merchant groups. Seven transactions qualified for temporal holdout. Broad-category accuracy was 5/7 (71.43%); exact category/subcategory accuracy was 4/7 (57.14%). Five predictions were automatic: all five had the correct broad category, four had the exact label. The remaining mismatch predicted the Food parent rather than the manually selected Dinner subcategory, with no reliable clock inferred. Two predictions required review. Full-history analysis proposed seven historical rules with no contradictory merchant groups; these were not saved.

This small repeat-merchant sample is not overall production accuracy. The evaluation does not measure all saved rules, email/account parsing, refunds, or the personal-UPI heuristic: ledger-only exports lack the necessary recipient metadata. Insufficient evidence and absent subcategories must remain visible rather than being reported as successful exact predictions. Tests cover held-out corrections, exclusion of machine enrichment, same-day leakage and input preservation.
