# Historical Gmail preview

Settings → Gmail → Historical Gmail preview scans an explicit range (at most 100 days), independently of the incremental connection start date/cursor. The initial range is 18 July through 18 October 2026, inclusive in IST. Only allowlisted bank senders with existing parsers are covered. Provider receipts, attachments and unsupported formats are not a complete account history.

Migration 0019 adds two staging tables with owner-only SELECT RLS; writes are server-only. A shared Gmail connection lease serializes discovery with ordinary sync/disconnect. The run's query is immutable. Message IDs are durably queued before cursor advance, and a replay uses a unique run/message key. Cursor recovery can restart the same query without erasing queued results. Each request lists at most 25 IDs and processes at most 25 observations within a time budget; the UI performs six requests and then offers Continue. Failed messages have at most three processing attempts. Terminal completion requires discovery exhaustion, no queued observations and no failed messages. A completed run is returned unchanged on retry of its same date range.

The preview never writes ledger transactions, normal Gmail receipts, learned rules, recurring links or balances. Existing ignored receipts remain ignored. Existing logged IDs and unique strong account/reference/direction/amount matches point to the existing canonical transaction. Amount/date collisions, orphan source identities, unknown accounts, credits, financial-purpose uncertainty and category uncertainty remain reviewable. Unsupported messages are reported as skipped. Counts distinguish discovered, processed, matched, proposed, review, ignored, skipped and failed; imported is always zero for a preview. Export contains extracted details and evidence, not raw email bodies or OAuth credentials.

Recurring suggestions reuse existing rules and actual expense transactions. Unique exact merchant/account/amount matches propose a link; different amounts propose review. Income, refunds and ambiguous merchants never count as paid subscriptions. Existing recurring links are retained. Additional known subscription merchants need three distinct monthly charges with 25–35 day gaps to suggest a pattern. Rules, forecasts and paid status remain unchanged until approved links are applied. No payment is synthesized from a renewal reminder or a mandate.

Historical import/link approval is a separate step: back up current data, review the complete exported preview against statements, use the shared source identity and atomic ledger functions, and reject stale/ambiguous matches. A completed scan is neither an approval nor a statement reconciliation. This phase deliberately has no one-click historical apply endpoint. Do not feed staging IDs into the ordinary pending Gmail queue.

Relevant files: `src/lib/gmail/backfill.ts`, `backfill-plan.ts`, `src/app/api/gmail/backfill/route.ts`, `src/components/settings/gmail-backfill.tsx`, `supabase/migrations/0019_gmail_backfill_preview.sql`. Nightly scheduling and automatic recurring-rule creation are separate phases.
