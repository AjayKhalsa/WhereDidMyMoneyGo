# Calculation audit: net outflows and cash safety

Inspected 21 October 2026 against main containing PR #22. No live ledger, production migration state, statements or Vercel billing access was available. The user confirms statement reconciliation was completed in another chat; this audit preserves it and changes calculations/display only. No transaction is inserted, merged, relabelled or financially adjusted.

## Boundaries

An unrecorded credit cannot appear in a calculated total. A credit filed in another category cannot safely be inferred as a Family transfers credit from matching value or payee alone. The screenshot's actual ₹80,000 requires a recorded, correctly attributed credit; the regression uses synthetic evidence and does not assert a production reconciliation.

Category net outflow and consumption spending intentionally answer different questions. For ₹140,000 outgoing and ₹80,000 ordinary categorized credits: category net outflow is ₹60,000; recorded income includes the ₹80,000 and consumption remains ₹140,000 unless the credit is actually a refund. The surplus therefore already reflects the ₹80,000 once. This prevents double-counting a credit as both earnings and reduced expense.

Averages compare whole recorded cycles; the explorer separately compares matched elapsed dates in an ongoing cycle. Neither proves historical data coverage. Portfolio values use user-stamped valuations and linked withdrawals; there is no price feed, historical valuation series or inferred attribution for unlinked redemptions. Archived/active-account and holding selections retain existing behavior. Foreign-browser calendar handling and missing account/counterparty classifications require separate evidence; this audit does not certify every possible private ledger or provider template.

## Validation and deployment

Focused regressions in `tests/engine/calculation-audit.test.ts` cover cash-flow signs, exact evidence rows, cross-cycle refunds, cash safety, card credits, investment conservation and recurring status. Existing accounting, reconciliation, source-identity and RLS suites remain part of verification. No database migration is required for these calculation changes.

The user also requested four daily Gmail syncs. That schedule is isolated in a separate change because Vercel Hobby rejects cron expressions more frequent than daily during deployment. Target IST times are 03:00, 09:00, 15:00 and 21:00, using UTC `30 3,9,15,21 * * *`. The existing endpoint, authentication, leases and duplicate protections are reused. See https://vercel.com/docs/cron-jobs/usage-and-pricing. Neither a paid plan nor successful live runs was verified here.

Completed validation: 567 tests across 44 files passed individually, plus the production build/type check. Chromium at phone width verified Home, the Family transfers drill-down and the explorer with synthetic five-debit/one-credit data: ₹140,000 outgoing, ₹80,000 credited, ₹60,000 net, six source rows and unchanged ledger types/values. These are code and fixture validations, not live balance certification.
